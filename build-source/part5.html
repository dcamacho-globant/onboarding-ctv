Video: how MediaKind works

MediaKind es uno de los proveedores de streaming. La app no siempre lo usa: depende de flags y del tipo de contenido. Cuando aplica, el servidor de la NFL devuelve un "paquete" (mediakindPayload) con la configuración y la sesión, y el reproductor lo usa para armar la fuente y conectarse a MediaKind.

MediaKind is one of the streaming providers. The app does not always use it: it depends on flags and on the type of content. When it applies, the NFL server returns a "package" (mediakindPayload) with the configuration and the session, and the player uses it to build the source and connect to MediaKind.

  1. ¿Aplica MediaKind a este video? CTVVideo lee 5 flags de Flagsmith ({{C:src/constants/features.ts:23}}) y los junta en mediakindFlags ({{C:src/components/CTVVideo/CTVVideo.tsx:220}}). La regla está en {{P:apps/shared/src/utils/mediakind.ts:13}}: si el video trae provider: "lura" no aplica; si trae "mediakind" sí; si no, decide según el canal (NFL Channel, NFL Network), si es en vivo o el tipo de VOD. El hook {{P:video/src/components/VideoPlayer/hooks/useEnableMediakind.ts:17}} aplica esa regla al video que se va a cargar.
  2. Se pide el token de reproducción. En {{P:video/src/components/VideoPlayer/utils/getLuraVideo.ts:454}} se leen los tokens STS guardados y se envían al endpoint /play/v1/asset/{id} con enableMediakind=true ({{P:nfl-api/src/play/Play.ts:46}}).
  3. Llega el paquete. Si la respuesta dice provider === "mediakind", el campo player se usa como mediakindPayload ({{P:video/src/components/VideoPlayer/utils/getLuraVideo.ts:584}}) y se pega al video ({{P:video/src/components/VideoPlayer/utils/getLuraVideo.ts:394}}).
  4. Se guardan los tokens STS. {{P:video/src/atoms/utils/cacheMediaKindStsTokens.ts:75}} guarda el token que viene en la respuesta, uno por suscripción y por ambiente (producción o staging), en almacenamiento persistente ({{P:video/src/atoms/jotai-clean-states/mediaKindStsTokensAtom.ts:10}}). Al leerlos ({{P:video/src/atoms/utils/cacheMediaKindStsTokens.ts:106}}) se descartan los vencidos y los de planes a los que el usuario ya no tiene acceso. Así se reutilizan en la siguiente reproducción.
  5. Se arma la fuente. {{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:1798}} revisa MediaKind primero (antes que THEOlive) y llama a {{P:video/src/components/TheoVideoPlayer/utils/commonUtils.ts:211}}. En vivo, el src es organización/externalId más un sufijo con el id de sesión en web y Android, para que cada reproducción tenga su propia sesión ({{P:video/src/components/TheoVideoPlayer/utils/commonUtils.ts:255}}). En VOD se usa la URL del video y se configura el DRM ({{P:video/src/components/TheoVideoPlayer/utils/commonUtils.ts:260}}).
  6. Se conecta el conector. En setSource se crea el conector de MediaKind con la configuración del paquete ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:2287}}, creado en {{P:video/src/components/TheoVideoPlayer/utils/connectorsUtils.ts:681}}) y se le pasa la sesión ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:2296}}).
  7. Se escuchan los cambios de programa. El hook {{P:video/src/components/TheoVideoPlayer/hooks/connectorHooks/useMediaKindConnector.ts:24}} escucha PROGRAM_UPDATE ({{P:video/src/components/TheoVideoPlayer/hooks/connectorHooks/useMediaKindConnector.ts:65}}). La primera actualización al entrar al stream se trata como "unirse", no como cambio de programa ({{P:video/src/components/VideoPlayer/utils/mediakindJoinGate.ts:17}}). Si llega un fin de programa ({{P:video/src/components/VideoPlayer/utils/isMediaKindProgramEnd.ts:19}}), se espera un momento ({{P:video/src/components/VideoPlayer/utils/isMediaKindProgramEnd.ts:11}}) por si empieza el siguiente antes de dar el stream por terminado.
  1. Does MediaKind apply to this video? CTVVideo reads 5 Flagsmith flags ({{C:src/constants/features.ts:23}}) and groups them into mediakindFlags ({{C:src/components/CTVVideo/CTVVideo.tsx:220}}). The rule lives in {{P:apps/shared/src/utils/mediakind.ts:13}}: a video with provider: "lura" does not use it; "mediakind" does; otherwise it depends on the channel (NFL Channel, NFL Network), whether it is live, or the VOD type. The hook {{P:video/src/components/VideoPlayer/hooks/useEnableMediakind.ts:17}} applies that rule to the video about to load.
  2. The play token is requested. {{P:video/src/components/VideoPlayer/utils/getLuraVideo.ts:454}} reads the stored STS tokens and sends them to the /play/v1/asset/{id} endpoint with enableMediakind=true ({{P:nfl-api/src/play/Play.ts:46}}).
  3. The package arrives. If the response says provider === "mediakind", the player field becomes the mediakindPayload ({{P:video/src/components/VideoPlayer/utils/getLuraVideo.ts:584}}) and is attached to the video ({{P:video/src/components/VideoPlayer/utils/getLuraVideo.ts:394}}).
  4. STS tokens are stored. {{P:video/src/atoms/utils/cacheMediaKindStsTokens.ts:75}} saves the token from the response, one per subscription and per environment (production or staging), in persistent storage ({{P:video/src/atoms/jotai-clean-states/mediaKindStsTokensAtom.ts:10}}). When read ({{P:video/src/atoms/utils/cacheMediaKindStsTokens.ts:106}}), expired tokens and those for plans the user no longer has are dropped. They are reused on the next playback.
  5. The source is built. {{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:1798}} checks MediaKind first (before THEOlive) and calls {{P:video/src/components/TheoVideoPlayer/utils/commonUtils.ts:211}}. For live, src is organization/externalId plus a session-id suffix on web and Android, so each playback gets its own session ({{P:video/src/components/TheoVideoPlayer/utils/commonUtils.ts:255}}). For VOD it uses the video URL and configures DRM ({{P:video/src/components/TheoVideoPlayer/utils/commonUtils.ts:260}}).
  6. The connector is attached. In setSource the MediaKind connector is created with the package's config ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:2287}}, built in {{P:video/src/components/TheoVideoPlayer/utils/connectorsUtils.ts:681}}) and given the session ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:2296}}).
  7. Program changes are tracked. The hook {{P:video/src/components/TheoVideoPlayer/hooks/connectorHooks/useMediaKindConnector.ts:24}} listens for PROGRAM_UPDATE ({{P:video/src/components/TheoVideoPlayer/hooks/connectorHooks/useMediaKindConnector.ts:65}}). The first update when joining the stream is treated as "joining", not as a program change ({{P:video/src/components/VideoPlayer/utils/mediakindJoinGate.ts:17}}). A program-end cue ({{P:video/src/components/VideoPlayer/utils/isMediaKindProgramEnd.ts:19}}) waits briefly ({{P:video/src/components/VideoPlayer/utils/isMediaKindProgramEnd.ts:11}}) in case the next program starts right behind it before the stream is considered finished.
