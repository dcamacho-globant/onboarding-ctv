Cómo funciona el login

How login works

  1. Dónde empieza. El login se pide desde varias pantallas, por ejemplo el onboarding ({{C:src/screens/OnboardingScreen/OnboardingPromo/OnboardingPromo.tsx:214}}) o la pantalla de NFL+ ({{C:src/screens/NflPlusUpsellScreen/NflPlusUpsellScreen.tsx:402}}). Todas llaman a AuthenticationManager.authenticateNflAccount ({{C:src/managers/AuthenticationManager/AuthenticationManager.ts:102}}). Para entrar con el proveedor de TV existe authenticateTvProvider ({{C:src/managers/AuthenticationManager/AuthenticationManager.ts:86}}).
  2. Se abre la pantalla de cuenta. _authenticate ({{C:src/managers/AuthenticationManager/AuthenticationManager.ts:43}}) crea el servicio, lo arranca y abre AccountScreen ({{C:src/managers/AuthenticationManager/AuthenticationManager.ts:59}}), que se suscribe a los avisos del servicio.
  3. La TV pide un código. NFLAccountAuthenticationService pide un código de activación (regCode) al servidor ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:99}}, definido en {{P:apps/shared/src/utils/api/utilities.ts:99}}). La pantalla lo muestra junto con la dirección donde se escribe ({{C:src/screens/AccountScreen/AccountScreen.tsx:378}}, {{C:src/screens/AccountScreen/AccountScreen.tsx:231}}).
  4. La TV deja una "nota" en el servidor. Sin OIDC, guarda los datos del dispositivo en el almacén temporal (KeyStore) bajo ese código ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:118}}, {{P:nfl-api/src/KeyStore/KeyStore.ts:41}}). Con el flag de OIDC activo ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:109}}) se usa PKCE: genera un verificador y un desafío ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:158}}, {{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:185}}).
  5. El usuario confirma en otro dispositivo. Entra a la dirección mostrada desde el celular o la computadora, escribe el código e inicia sesión. Ese paso ocurre fuera de este código.
  6. La TV pregunta cada pocos segundos. onQueryServer consulta el KeyStore con el mismo código ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:274}}, {{P:nfl-api/src/KeyStore/KeyStore.ts:12}}). Si aún no hay respuesta, el error "timeout" vuelve a programar la consulta ({{C:src/managers/AuthenticationManager/services/BaseAuthenticationService.ts:231}}) hasta agotar los reintentos.
  7. Llega la respuesta. Sin OIDC trae el UID del usuario y su firma; con OIDC trae un código de autorización que se cambia por tokens (handleOidcTokenExchange). Los datos se guardan ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:305}}) y se pide el perfil completo ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:318}}).
  8. Se termina. onActivated ({{C:src/managers/AuthenticationManager/services/BaseAuthenticationService.ts:173}}) avisa el éxito, revisa si el plan está pausado o si es suscriptor, y vuelve a la pantalla anterior o ejecuta el callback.
  1. Where it starts. Login is requested from several screens, for example onboarding ({{C:src/screens/OnboardingScreen/OnboardingPromo/OnboardingPromo.tsx:214}}) or the NFL+ screen ({{C:src/screens/NflPlusUpsellScreen/NflPlusUpsellScreen.tsx:402}}). All of them call AuthenticationManager.authenticateNflAccount ({{C:src/managers/AuthenticationManager/AuthenticationManager.ts:102}}). Signing in with a TV provider uses authenticateTvProvider ({{C:src/managers/AuthenticationManager/AuthenticationManager.ts:86}}).
  2. The account screen opens. _authenticate ({{C:src/managers/AuthenticationManager/AuthenticationManager.ts:43}}) creates the service, starts it and opens AccountScreen ({{C:src/managers/AuthenticationManager/AuthenticationManager.ts:59}}), which subscribes to the service's notices.
  3. The TV asks for a code. NFLAccountAuthenticationService requests an activation code (regCode) from the server ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:99}}, defined in {{P:apps/shared/src/utils/api/utilities.ts:99}}). The screen shows it together with the address where it is typed ({{C:src/screens/AccountScreen/AccountScreen.tsx:378}}, {{C:src/screens/AccountScreen/AccountScreen.tsx:231}}).
  4. The TV leaves a "note" on the server. Without OIDC it stores the device data in a temporary store (KeyStore) under that code ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:118}}, {{P:nfl-api/src/KeyStore/KeyStore.ts:41}}). With the OIDC flag on ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:109}}) it uses PKCE: it generates a verifier and a challenge ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:158}}, {{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:185}}).
  5. The user confirms on another device. They open the shown address on a phone or computer, type the code and sign in. That step happens outside this code.
  6. The TV asks every few seconds. onQueryServer reads the KeyStore with the same code ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:274}}, {{P:nfl-api/src/KeyStore/KeyStore.ts:12}}). If there is no answer yet, the "timeout" error schedules another check ({{C:src/managers/AuthenticationManager/services/BaseAuthenticationService.ts:231}}) until retries run out.
  7. The answer arrives. Without OIDC it carries the user's UID and signature; with OIDC it carries an authorization code that is exchanged for tokens (handleOidcTokenExchange). The data is saved ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:305}}) and the full profile is requested ({{C:src/managers/AuthenticationManager/services/NFLAccountAuthenticationService.ts:318}}).
  8. It finishes. onActivated ({{C:src/managers/AuthenticationManager/services/BaseAuthenticationService.ts:173}}) announces success, checks whether the plan is paused or the user is a subscriber, and goes back or runs the callback.
