Cómo funciona Redfast

How Redfast works

Redfast muestra mensajes promocionales (por ejemplo, ofertas de suscripción) como banners y ventanas. Se activa con el flag FEATURE_ENABLE_REDFAST ({{C:src/constants/features.ts:70}}). Funciona distinto en web y en nativo.

Redfast shows promotional messages (for example, subscription offers) as banners and overlays. It is turned on by the FEATURE_ENABLE_REDFAST flag ({{C:src/constants/features.ts:70}}). It works differently on web and on native.

En CTV Web

On CTV Web

  1. Se carga como un script externo. RedfastProvider envuelve la app ({{C:src/App.web.tsx:383}}). Si el flag está activo, llama a loadRedfastSDK ({{C:src/utils/RedfastProvider.web.tsx:32}}), que guarda el tipo de dispositivo, agrega el <script> del SDK (producción o staging) a la página y le pone el atributo data-rf-device-type ({{C:src/utils/loadSDKs.web.ts:673}}, {{C:src/utils/loadSDKs.web.ts:697}}). Si falla, se registra el error.
  2. El SDK dibuja los mensajes. En web, la interfaz la pinta el propio script de Redfast, no React. Por eso RedfastHost no hace nada en web ({{C:src/components/ModalContent/RedfastHost/RedfastHost.web.tsx:1}}).
  3. Se escucha un evento. Cuando el usuario presiona un botón, Redfast lanza el evento redfast-ctvweb-event ({{C:src/utils/RedfastProvider.web.tsx:13}}). El proveedor busca en window.Redfast la acción de ese botón y lee su rf_settings_deeplink ({{C:src/utils/RedfastProvider.web.tsx:58}}).
  4. Se navega. Ese enlace profundo pasa al manejador de deeplinks de la app ({{C:src/utils/RedfastProvider.web.tsx:65}}), el mismo que usan otras entradas, y lleva al usuario a la pantalla correspondiente.
  1. It loads as an external script. RedfastProvider wraps the app ({{C:src/App.web.tsx:383}}). If the flag is on, it calls loadRedfastSDK ({{C:src/utils/RedfastProvider.web.tsx:32}}), which stores the device type, adds the SDK <script> (production or staging) to the page and sets the data-rf-device-type attribute ({{C:src/utils/loadSDKs.web.ts:673}}, {{C:src/utils/loadSDKs.web.ts:697}}). If it fails, the error is logged.
  2. The SDK draws the messages. On web the Redfast script itself paints the UI, not React. That is why RedfastHost does nothing on web ({{C:src/components/ModalContent/RedfastHost/RedfastHost.web.tsx:1}}).
  3. An event is heard. When the user presses a button, Redfast fires the redfast-ctvweb-event event ({{C:src/utils/RedfastProvider.web.tsx:13}}). The provider looks up that button's action in window.Redfast and reads its rf_settings_deeplink ({{C:src/utils/RedfastProvider.web.tsx:58}}).
  4. The app navigates. That deep link goes to the app's deeplink handler ({{C:src/utils/RedfastProvider.web.tsx:65}}), the same one other entry points use, and takes the user to the matching screen.

En nativo (tvOS, Fire TV, Android TV)

On native (tvOS, Fire TV, Android TV)

  1. Se usa un SDK de React Native. La app elige el ID de Redfast según el ambiente ({{C:src/App.tsx:307}}) y lo pasa a PromptProvider, junto con el id del dispositivo ({{C:src/App.tsx:324}}). Ese proveedor viene del SDK de Recurly Engage ({{C:src/utils/usePromptShim.ts:1}}); en web se usa una versión vacía ({{C:src/utils/usePromptShim.web.ts:14}}).
  2. Se inicia en el Splash. useRedfastInit ({{C:src/hooks/useRedfastInit.ts:20}}) espera, hasta 10 intentos ({{C:src/hooks/useRedfastInit.ts:18}}), a que el SDK esté listo ({{C:src/hooks/useRedfastInit.ts:47}}) y entonces le asigna las fuentes de la app. Solo corre en nativo, con el flag activo y con el usuario identificado. Se llama desde {{C:src/screens/SplashScreen/SplashScreen.tsx:242}}.
  3. Se identifica al usuario. useRedfastAuth ({{C:src/hooks/useRedfastAuth.ts:9}}) le pasa el UID de Gigya al SDK ({{C:src/hooks/useRedfastAuth.ts:24}}) para que los mensajes sean personalizados.
  4. Se pintan los mensajes. RedfastHost vive dentro del menú lateral ({{C:src/navigators/SideBarNavigator.tsx:199}}) para tener contexto de navegación. Muestra el PromptOverlay ({{C:src/components/ModalContent/RedfastHost/RedfastHost.tsx:38}}) cuando el SDK lo pide. El banner de Home llega como una bandeja de tipo RedfastBanner ({{C:src/utils/useFetchTrays.ts:815}}).
  5. Se reacciona al botón. useRedfast ({{C:src/hooks/useRedfast.ts:40}}) registra la analítica del mensaje ({{C:src/hooks/useRedfast.ts:148}}) y, si el botón trae un enlace, lo envía al manejador de deeplinks ({{C:src/hooks/useRedfast.ts:246}}). Una impresión (el banner solo se ve) no navega.
  1. It uses a React Native SDK. The app picks the Redfast ID by environment ({{C:src/App.tsx:307}}) and passes it to PromptProvider together with the device id ({{C:src/App.tsx:324}}). That provider comes from the Recurly Engage SDK ({{C:src/utils/usePromptShim.ts:1}}); on web an empty stand-in is used ({{C:src/utils/usePromptShim.web.ts:14}}).
  2. It starts on the Splash screen. useRedfastInit ({{C:src/hooks/useRedfastInit.ts:20}}) waits, up to 10 attempts ({{C:src/hooks/useRedfastInit.ts:18}}), for the SDK to be ready ({{C:src/hooks/useRedfastInit.ts:47}}) and then sets the app's fonts on it. It runs only on native, with the flag on and a known user. It is called from {{C:src/screens/SplashScreen/SplashScreen.tsx:242}}.
  3. The user is identified. useRedfastAuth ({{C:src/hooks/useRedfastAuth.ts:9}}) gives the Gigya UID to the SDK ({{C:src/hooks/useRedfastAuth.ts:24}}) so messages can be personalized.
  4. Messages are drawn. RedfastHost lives inside the side menu ({{C:src/navigators/SideBarNavigator.tsx:199}}) to have navigation context. It shows the PromptOverlay ({{C:src/components/ModalContent/RedfastHost/RedfastHost.tsx:38}}) when the SDK asks for it. The Home banner arrives as a RedfastBanner tray ({{C:src/utils/useFetchTrays.ts:815}}).
  5. It reacts to the button. useRedfast ({{C:src/hooks/useRedfast.ts:40}}) records the message analytics ({{C:src/hooks/useRedfast.ts:148}}) and, if the button carries a link, sends it to the deeplink handler ({{C:src/hooks/useRedfast.ts:246}}). An impression (the banner is merely visible) does not navigate.
