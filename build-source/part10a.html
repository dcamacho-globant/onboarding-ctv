How analytics works (Adobe on web and React Native)

Connected usa Adobe como herramienta de analítica, pero no con el mismo SDK en las dos plataformas. En nativo usa el SDK de Adobe para React Native (Adobe Experience Platform Mobile). En web carga Adobe Launch, un script que la página descarga, y le manda los eventos. El código que dispara los eventos es el mismo; lo que cambia es el archivo que los entrega a Adobe (.native o .web).

Connected uses Adobe for analytics, but not the same SDK on both platforms. On native it uses the Adobe React Native SDK (Adobe Experience Platform Mobile). On web it loads Adobe Launch, a script the page downloads, and sends events to it. The code that fires events is the same; what changes is the file that hands them to Adobe (.native or .web).

Arranque

Startup

  1. Nativo. En el Splash se llama a AdobeTrackingManager.init ({{C:src/screens/SplashScreen/SplashScreen.tsx:163}}), que configura el SDK con el ID de Adobe del ambiente ({{C:src/managers/AdobeTrackingManager/AdobeTrackingManager.ts:30}}, ID en {{C:application.config.js:201}}). Antes de iniciar, el contenedor comprueba que el servicio de Adobe (Edge) sea alcanzable, para no reintentar sin parar si un bloqueador lo corta ({{P:apps/shared/src/containers/AdobeExperiencePlatform.ts:158}}). Luego llama a MobileCore.initialize ({{P:apps/shared/src/containers/AdobeExperiencePlatform.ts:151}}).
  2. Web. La App web agrega un <script> con la librería de Launch ({{C:src/App.web.tsx:299}}). Hay dos versiones: la URL de Adobe para navegadores modernos y una copia transpilada para TVs viejas ({{C:src/utils/getAdobeLaunchSrc.ts:4}}, generada por {{C:scripts/fetchAdobeLaunch.js:94}}). Si el script no carga, la app deja un _satellite falso para que nada se rompa ({{C:src/App.web.tsx:301}}). Por eso en web el manager marca Adobe como listo sin configurarlo ({{C:src/managers/AdobeTrackingManager/AdobeTrackingManager.ts:25}}).
  3. Consentimiento. Antes de enviar algo, el código revisa que el usuario haya aceptado el SDK de Adobe ({{P:apps/shared/src/utils/consent.ts:324}}).
  1. Native. On the Splash screen AdobeTrackingManager.init is called ({{C:src/screens/SplashScreen/SplashScreen.tsx:163}}), which configures the SDK with the environment's Adobe ID ({{C:src/managers/AdobeTrackingManager/AdobeTrackingManager.ts:30}}, ID in {{C:application.config.js:201}}). Before starting, the container checks that Adobe's service (Edge) is reachable, so it does not retry forever if a blocker cuts it off ({{P:apps/shared/src/containers/AdobeExperiencePlatform.ts:158}}). Then it calls MobileCore.initialize ({{P:apps/shared/src/containers/AdobeExperiencePlatform.ts:151}}).
  2. Web. The web App adds a <script> with the Launch library ({{C:src/App.web.tsx:299}}). There are two versions: Adobe's URL for modern browsers and a transpiled copy for old TVs ({{C:src/utils/getAdobeLaunchSrc.ts:4}}, generated by {{C:scripts/fetchAdobeLaunch.js:94}}). If the script fails to load, the app leaves a fake _satellite so nothing breaks ({{C:src/App.web.tsx:301}}). That is why on web the manager marks Adobe as ready without configuring it ({{C:src/managers/AdobeTrackingManager/AdobeTrackingManager.ts:25}}).
  3. Consent. Before sending anything, the code checks that the user accepted the Adobe SDK ({{P:apps/shared/src/utils/consent.ts:324}}).

Visitor identity (MCID)

Adobe identifica a cada visitante con un ID (Marketing Cloud ID). updateTrackingValues ({{C:src/managers/AdobeTrackingManager/AdobeTrackingManager.ts:60}}) lo lee, reintentando hasta un tiempo límite, y lo guarda en un atom ({{C:src/atoms/adobeTrackingState.ts:5}}). En nativo lo lee del SDK ({{P:apps/shared/src/containers/AdobeExperiencePlatform.ts:198}}); en web, de _satellite ({{C:src/utils/getUserMcmId.ts:6}}).
