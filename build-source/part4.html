Cómo funciona CTVWeb - Connected

How CTVWeb - Connected works

  1. Arranca. index.js carga platformIndex; Metro elige la versión web ({{C:platformIndex.web.js:15}}) o nativa. El build web usa CONNECTED_WEB=true expo export -p web.
  2. Se prepara. La App raíz inicia Sentry y el LogManager ({{C:src/App.tsx:203}}), enciende los flags ({{C:src/App.tsx:193}}) y espera a que estén listos ({{C:src/App.tsx:221}}).
  3. Sabe quién eres. AuthenticationManager ({{C:src/managers/AuthenticationManager/AuthenticationManager.ts:20}}) maneja el login. Los tokens se guardan en almacenamiento cifrado (MMKV) mediante atoms ({{C:src/atoms/authenticationState.ts:10}}).
  4. Muestra pantallas. El navegador abre DynamicScreen ({{C:src/navigators/RootStackNavigator.tsx:250}}), una pantalla cuyo contenido llega de la API en vez de estar fijo.
  5. Pide datos. Un hook de React Query llama a experienceApi, que consigue el token con NFLAPIConfig.getAuthToken() ({{C:src/nflApi/Experience.ts:77}}) y hace la petición con fetchId ({{C:src/nflApi/Experience.ts:78}}). React Query guarda la respuesta en caché.
  6. Guarda el estado. Jotai mantiene el estado compartido (por ejemplo, experienceFetchStatus en {{C:src/atoms/experienceState.ts:8}}).
  7. Se maneja con el control remoto. Las teclas llegan a KeyEventManager ({{C:src/managers/KeyEventManager.ts:18}}); en web, {{C:platformIndex.web.js:13}} hace que el gamepad se comporte como teclado.
  8. Reproduce. Al elegir un video, CTVVideo revisa si el contenido está bloqueado ({{C:src/utils/video.ts:94}}) y renderiza el reproductor, que arma la fuente del stream (ver "El viaje de la URL del video").
  9. Vigila. Los errores van a Sentry ({{C:src/utils/sentry.ts:88}}) por el LogManager ({{C:src/managers/LogManager/LogManager.ts:175}}), y la analítica a Adobe ({{C:src/managers/AdobeTrackingManager/AdobeTrackingManager.ts:12}}).
  1. It starts. index.js loads platformIndex; Metro picks the web ({{C:platformIndex.web.js:15}}) or native version. The web build uses CONNECTED_WEB=true expo export -p web.
  2. It gets ready. The root App starts Sentry and the LogManager ({{C:src/App.tsx:203}}), turns on the flags ({{C:src/App.tsx:193}}) and waits until they are ready ({{C:src/App.tsx:221}}).
  3. It knows who you are. AuthenticationManager ({{C:src/managers/AuthenticationManager/AuthenticationManager.ts:20}}) handles login. Tokens are kept in encrypted storage (MMKV) through atoms ({{C:src/atoms/authenticationState.ts:10}}).
  4. It shows screens. The navigator opens DynamicScreen ({{C:src/navigators/RootStackNavigator.tsx:250}}), a screen whose content comes from the API instead of being fixed.
  5. It asks for data. A React Query hook calls experienceApi, which gets the token with NFLAPIConfig.getAuthToken() ({{C:src/nflApi/Experience.ts:77}}) and makes the request with fetchId ({{C:src/nflApi/Experience.ts:78}}). React Query caches the response.
  6. It keeps state. Jotai holds the shared state (for example, experienceFetchStatus in {{C:src/atoms/experienceState.ts:8}}).
  7. It is driven by the remote. Key presses reach KeyEventManager ({{C:src/managers/KeyEventManager.ts:18}}); on web, {{C:platformIndex.web.js:13}} makes the gamepad behave like a keyboard.
  8. It plays. When a video is chosen, CTVVideo checks whether the content is locked ({{C:src/utils/video.ts:94}}) and renders the player, which builds the stream source (see "The video URL journey").
  9. It watches itself. Errors go to Sentry ({{C:src/utils/sentry.ts:88}}) via the LogManager ({{C:src/managers/LogManager/LogManager.ts:175}}), and analytics go to Adobe ({{C:src/managers/AdobeTrackingManager/AdobeTrackingManager.ts:12}}).

El viaje de la URL del video

The video URL journey

  1. Una tarjeta abre la pantalla de video y le pasa una lista (playlist) como parámetro de navegación: {{C:src/navigators/RootStackNavigator.tsx:399}}.
  2. VideoScreen entrega esa lista a CTVVideoWrapper como videos: {{C:src/screens/VideoScreen/VideoScreen.tsx:527}}.
  3. CTVVideo toma el video actual de la lista ({{C:src/components/CTVVideo/CTVVideo.tsx:176}}) y pasa la lista al reproductor ({{C:src/components/CTVVideo/CTVVideo.tsx:622}}).
  4. El reproductor THEOplayer arma la fuente en getSource ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:1742}}). Ahí se arma sources: [{ src, type, ... }] ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:1849}}). Según el caso usa un conector (MediaKind, THEOlive) o la URL directa. Para DASH, primero descarga el manifiesto y saca la URL real ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:3013}}).
  5. setSource ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:2143}}) llama a getSource ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:3069}}) y se la da al reproductor: this.player.source = source ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:2323}}).
  1. A card opens the video screen and passes it a list (playlist) as a navigation parameter: {{C:src/navigators/RootStackNavigator.tsx:399}}.
  2. VideoScreen hands that list to CTVVideoWrapper as videos: {{C:src/screens/VideoScreen/VideoScreen.tsx:527}}.
  3. CTVVideo takes the current video from the list ({{C:src/components/CTVVideo/CTVVideo.tsx:176}}) and passes the list to the player ({{C:src/components/CTVVideo/CTVVideo.tsx:622}}).
  4. The THEOplayer wrapper builds the source in getSource ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:1742}}). It assembles sources: [{ src, type, ... }] ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:1849}}). Depending on the content it uses a connector (MediaKind, THEOlive) or the direct URL. For DASH it first downloads the manifest and extracts the real URL ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:3013}}).
  5. setSource ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:2143}}) calls getSource ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:3069}}) and gives the result to the player: this.player.source = source ({{P:video/src/components/TheoVideoPlayer/TheoVideoPlayer.tsx:2323}}).
